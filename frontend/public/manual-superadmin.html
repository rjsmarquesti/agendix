Multi-tenancy

Cada empresa cliente é um Tenant. Todos os dados são isolados por tenantId — leads, agendamentos, usuários, configurações e financeiro são completamente separados entre tenants. O super admin tem visão global de todos.

Autenticação

  • Tenants — login em /login, JWT com expiração de 7 dias.
  • Super admin — login isolado em /admin/login, mesmo mecanismo JWT mas com role super_admin.
  • n8n / automações — autenticação por X-API-Token (por tenant) ou X-Master-Token (global).

3 Gestão de clientes (tenants)

Acesse em /admin/clientes. É a tela central de operação do negócio.

Criar novo tenant

1Clique em + Novo Cliente
2Preencha os dados obrigatórios
  • Nome — nome da empresa.
  • Slug — identificador único (ex: clinica-ana). Usado na URL do agendamento público: /agendar/clinica-ana. Só letras minúsculas, números e hífens.
  • Cor primária — cor do painel e do formulário público do tenant.

  • Status — geralmente trial para novos clientes.

O sistema cria o tenant e automaticamente tenta criar uma instância Evolution API (se as variáveis de ambiente EVOLUTION_BASE_URL e EVOLUTION_GLOBAL_API_KEY estiverem configuradas).

4 WhatsApp — Evolution API

Como funciona

Cada tenant tem uma instância própria na Evolution API, identificada pelo slug do tenant. A instância é criada automaticamente ao cadastrar o tenant (se a variável EVOLUTION_BASE_URL estiver configurada).

Credenciais por tenant

  • evolutionInstance — nome da instância (igual ao slug).
  • evolutionApiKey — chave gerada pela Evolution API no momento da criação.
  • evolutionBaseUrl — URL base da Evolution API (https://api.divulgabr.com.br).

Conectar o número (QR Code)

1Tenant acessa Configurações → Integração
2Clica em Verificar status

Se aparecer "desconectado", clica em Gerar QR Code.

3Escaneia o QR Code no WhatsApp

WhatsApp → Dispositivos conectados → Conectar dispositivo. O badge fica verde em até 30 segundos.

O QR Code expira em ~60 segundos. Se o tenant não conseguir escanear a tempo, clica novamente em "Gerar QR Code".

Variáveis de ambiente necessárias (backend)

  • EVOLUTION_BASE_URL — URL da Evolution API.
  • EVOLUTION_GLOBAL_API_KEY — chave global para criar instâncias.

5 Bot de agendamento via WhatsApp

Existem duas formas de o cliente agendar pelo WhatsApp. São independentes — o tenant usa uma ou outra:

Agente IA (interno)Bot n8n (externo)
DependênciaEvolution API + Claude APIEvolution API + n8n
ConfiguraçãoConfigurações → Agente IAConfigurações → Bot / n8n
n8nAtivoNão exigidoExigido (ativado pelo super admin)
Custo extraClaude API (por token)n8n self-hosted (já existe)
FlexibilidadeAlta (prompt customizável)Média (fluxo fixo no workflow)

Agente IA — configuração

O tenant configura em Configurações → Agente IA:

  • Persona — nome do assistente (ex: "Ana").
  • Prompt base — instruções de comportamento. Quanto mais detalhado, melhor a qualidade do atendimento.
  • Horário de atendimento — o agente só responde nesse intervalo.
  • Mensagem fora do horário — enviada automaticamente se o cliente escrever fora do horário.
O Agente IA usa Claude Haiku — o modelo mais rápido e barato da Anthropic. O custo é baixo, mas depende da variável ANTHROPIC_API_KEY no backend.

Bot n8n — ativação pelo super admin

1Em /admin/clientes, clique no botão raio ⚡ do tenant

Fica roxo quando ativo. Isso libera a aba "Bot / n8n" com campos de webhook e provisioning no painel do tenant.

2O tenant acessa Configurações → Bot / n8n e clica em Provisionar workflows

O sistema cria dois workflows no n8n: bot de agendamento WA + notificações.

6 Lembretes automáticos

O backend possui um cron job interno (notificacaoService.js) que roda a cada hora e envia lembretes de agendamento diretamente pela Evolution API de cada tenant — sem depender do n8n.

Como ativar por tenant

O tenant acessa Configurações → Empresa e ativa o toggle "Lembretes automáticos diretos". Requer instância Evolution conectada.

Quando os lembretes são enviados

MomentoCampo marcado
1 dia antes do agendamentolembrete1dEnviado = true
No dia do agendamentolembreteDiaEnviado = true

O template da mensagem é configurado pelo tenant em Configurações → Agenda → "Lembrete WhatsApp". Variáveis disponíveis: {{nome}}, {{data}}, {{hora}}, {{servico}}.

Resumo diário por e-mail/WA

Um segundo cron roda a cada 30 minutos e verifica se algum tenant configurou o Resumo do dia (Configurações → Agenda). Se o horário configurado bater com o horário atual, envia a lista de agendamentos do dia por WhatsApp e/ou e-mail.

Os lembretes só são enviados para agendamentos com status marcado ou confirmado. Agendamentos cancelados ou realizados são ignorados.

7 Integração n8n (opcional)

O n8n é opcional no Agendix. Por padrão está desativado para todos os tenants. O super admin ativa individualmente conforme necessidade.

Quando usar o n8n

  • Tenant prefere o bot de agendamento via fluxo fixo (sem IA generativa).
  • Tenant precisa de automações customizadas (CRM externo, planilhas, e-mail marketing).
  • Tenant não quer usar créditos de Claude API.

Variáveis de ambiente (backend)

  • N8N_BASE_URL — URL do n8n self-hosted.
  • N8N_API_KEY — chave da API do n8n.
  • CRM_BASE_URL — URL pública do backend (usada nos workflows para callbacks).
  • MASTER_API_TOKEN — token para a rota /api/n8n/lembretes-globais.

8 Módulo financeiro

Financeiro dos tenants

Tenants com plano Pro ou superior têm acesso ao módulo de lançamentos financeiros. O super admin não acessa os dados financeiros dos tenants — cada empresa gerencia seus próprios lançamentos.

Financeiro da plataforma (AdminLancamento)

Acessado em /admin/financeiro. Registra as receitas e despesas do negócio Agendix (não dos clientes).

  • Dashboard — MRR, receita, despesa, saldo e tabela de pagamentos por tenant.
  • Lançamentos — CRUD de receitas e despesas da plataforma. Criados automaticamente quando o Mercado Pago processa um pagamento.
  • Fluxo de caixa — gráfico de barras com os últimos 12 meses (receita vs. despesa).

Integração Mercado Pago

Quando um tenant assina um plano:

  1. Frontend chama POST /api/payments/assinar com o plano desejado.
  2. Backend cria uma assinatura PreApproval no MP e retorna o init_point (URL de pagamento).
  3. Tenant é redirecionado para o MP para concluir o pagamento.
  4. MP chama o webhook POST /api/payments/webhook com o resultado.
  5. Backend atualiza planoStatus e cria um AdminLancamento de receita automaticamente.

Variáveis de ambiente (Mercado Pago)

  • MP_ACCESS_TOKEN
  • MP_PLAN_BASICO_ID, MP_PLAN_PRO_ID, MP_PLAN_PREMIUM_ID, MP_PLAN_BUSINESS_ID
  • MP_WEBHOOK_SECRET — para validar a assinatura do webhook.

9 Backups

Acessado em /admin/backups. Permite criar, baixar, restaurar e excluir backups completos.

Tipos de backup

  • Admin — backup global de todos os tenants e dados da plataforma.
  • Tenant — backup isolado de um tenant específico (leads, agendamentos, serviços, configurações, financeiro).

Criar backup

1Clique em + Novo Backup
2Escolha o tipo: Admin ou Tenant (selecione o tenant)
3Aguarde a geração. O arquivo JSON é salvo no volume agendix-backups no servidor.

Baixar backup

Clique no botão de download na linha do backup. O arquivo é baixado via fetch autenticado com JWT — funciona mesmo que o arquivo esteja em volume privado do container.

Restaurar backup

1Clique em Restaurar na linha do backup desejado
2Confirme a operação
A restauração substitui todos os dados atuais pelo conteúdo do backup. Esta ação não pode ser desfeita. Faça um backup da versão atual antes de restaurar.
Os arquivos de backup ficam no volume Docker agendix-backups (montado em /app/backups no container). Use Volume, nunca Bind Mount — o Bind Mount com path inexistente no host causa erro no EasyPanel.

10 Consumo de recursos

Acessado em /admin/consumo. Exibe barras de progresso por tenant mostrando o uso de agendamentos e usuários em relação ao limite do plano.

  • Verde — dentro do limite.
  • Vermelho — no limite ou próximo. Considere sugerir upgrade de plano ao cliente.
  • Tenants com plano Premium ou Business não têm limite — aparecem como "ilimitado".

13 Migração do CRM Simples

O script migrate-crm-to-agendix.js (em C:\Users\Rogério\) migra dados do CRM Simples (MySQL) para o Agendix (PostgreSQL).

O que é migrado

  • Tenants (empresas)
  • Usuários — com hash de senha preservado (mesmo login/senha funcionam no Agendix)
  • Leads (1:1 — mesmos campos)
  • Serviços
  • Configurações de agenda
  • Bloqueios de horário
  • Agendamentos

O que NÃO é migrado

  • conversas_whatsapp — estado volátil, descartado
  • Plano/assinatura MP — configurar manualmente após migração
  • n8n workflow IDs — re-provisionar pelo painel
  • Instâncias Evolution API — reconectar QR Code

Como executar (no terminal do container Agendix no EasyPanel)

1Instalar dependências temporárias
cd /tmp && npm install mysql2 pg
2Copiar o script para /tmp e executar
CRM_DB_URL="mysql://..." AGENDIX_DB_URL="$DATABASE_URL" node /tmp/migrate.js

Após a migração

  1. Configurar plano de cada tenant em /admin/clientes.
  2. Reconectar WhatsApp via QR Code para cada tenant.
  3. Re-provisionar n8n (se necessário) pelo botão no modal de detalhe do tenant.

14 Troubleshooting

ProblemaCausa mais provávelSolução
Tenant não consegue logar após migração Hash de senha incompatível (improvável) ou e-mail duplicado Resetar senha pelo painel /admin/clientes → modal detalhe
QR Code não aparece Instância Evolution não criada ou sem conexão Verificar variáveis EVOLUTION_BASE_URL e EVOLUTION_GLOBAL_API_KEY. Tentar recriar a instância pelo botão WA no admin.
Lembretes não são enviados lembretesDiretosAtivo = false ou Evolution desconectada Ativar toggle em Configurações → Empresa. Verificar conexão WA do tenant.
Limite de agendamentos atingido (HTTP 402) Tenant no limite do plano no mês corrente Upgrade de plano pelo painel admin (select inline na tabela).
Backup falha ao baixar Volume agendix-backups não montado Verificar volumes no EasyPanel. Usar Volume, não Bind Mount.
n8n provisioning falha Variáveis N8N_BASE_URL ou N8N_API_KEY ausentes Adicionar as variáveis no EasyPanel → serviço backend → Environment.
Migration falha no redeploy Conflito de migration ou banco inacessível Verificar logs do container. Conectar no terminal e rodar npx prisma migrate status.
Agente IA não responde ANTHROPIC_API_KEY ausente ou Agente IA desativado Verificar variável de ambiente. Confirmar que ativo = true na aba Agente IA do tenant.
Pagamento MP não atualiza plano Webhook não chegou ou MP_WEBHOOK_SECRET incorreto Verificar logs de auditoria. Confirmar URL do webhook configurada no painel do MP.
